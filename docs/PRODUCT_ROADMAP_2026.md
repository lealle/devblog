# DevBlog 제품 전략·확장 로드맵 (2026-11-02)

> 상태: **기획·실행 계획**. 이 문서에 적힌 신규 기능은 구현 완료를 의미하지 않는다. 기준: 2026-11-02의 `main` 코드와 PR #1 구현 보고서.

## 1. 제품 방향

**미션:** 기업·기관 엔지니어링 글을 단순 수집하는 RSS 목록에서, 개발자가 문제를 해결하고 기술을 학습할 때 신뢰할 만한 근거를 찾아주는 **기술 지식 탐색 허브**로 발전시킨다.

**비목표:** 무단 원문 복제, 검증되지 않은 AI 요약을 사실로 표시, 개인 블로그를 무분별하게 혼합, 초기 단계에서 서버·벡터 DB·유료 API 도입.

### 주요 사용자 과업

1. **문제 해결:** `Spring JPA N+1` → 원인, 대안, 적용 사례, 성능 검증 순서로 자료 탐색.
2. **학습:** `Kafka` → 선수 지식, 입문, 운영 사례, 장애 분석.
3. **기술 탐색:** `Kubernetes` → 최근 기술 변화와 관련 기업의 실전 사례.
4. **비교·의사결정:** `Redis vs Memcached` → 비교 관점과 원문 근거를 나란히 확인.
5. **출처 발견:** 회사·기관·언어·기술·발행 시기별 검색.

## 4. 상세 기술 보강

### 4.1 수집·정합성
- 피드 건강도: 최근 성공/실패, 응답시간, HTTP 상태, 304 비율, 연속 실패, 마지막 성공 시각을 집계한다.
- 실패 유형 분리: 일시적 429/5xx는 지수 백오프·Retry-After 고려, 404/410은 장기 휴면 후보, 네트워크 오류는 재시도한다.
- URL 정규화: `utm_*`, `fbclid` 등 추적 매개변수만 제거하고 의미 있는 쿼리는 보존한다. **기존 hash와 seen.txt 호환성을 유지하는 마이그레이션 테스트**를 선행한다.
- RSS 날짜 파싱: `*_parsed`만 있는 피드도 처리하고, 시간대/미래 날짜/날짜 없음 테스트를 추가한다.
- 보안: HTTP(S) 링크만 수용하고 DOM에는 `textContent`를 사용한다. 외부 리디렉션과 신뢰할 수 없는 HTML을 방어적으로 취급한다.
- GitHub Actions 동시 실행/재시도/커밋 충돌 시나리오와 Pages 아티팩트 일관성을 점검한다.

### 4.2 검색·색인
- 우선 실측: 문서 수, 색인 JSON 바이트, gzip 크기, 모바일 최초 로딩, 검색 응답 p50/p95.
- 한글·영문·약어·기술명 동의어: `JPA N+1`, `N plus one`, `엔플러스원` 등 동의어 확장; 정밀도 저하를 측정한다.
- 제목/본문 요약/출처 가중치, 최신성 감쇠, 중복 글 패널티를 설명 가능한 점수로 계산한다.
- 전체 JSON이 예산을 넘으면 날짜/분야별 분할 색인 또는 Pagefind PoC 비교. Pagefind는 **개별 글 색인 구조·한국어 처리·빌드 시간**을 검증한 뒤 선택한다.
- 빈 결과·오탈자·필터 해제·검색어 URL 공유·키보드 조작·모바일 접근성을 개선한다.

### 4.3 분류·추천
- 분류 데이터 모델: `topics[]`, `technologies[]`, `content_type`, `evidence[]`, `confidence`, `classifier_version`.
- `원인 → 해결 → 비교 → 검증` 경로는 **관련 문서 후보**이지 검증된 해결책이 아니라는 표시를 유지한다.
- 관련 문서 근거: 동일 기술 태그, 공통 오류 코드, 동일 출처의 후속 글, 공식 문서 매칭. 관계를 `related`, `prerequisite`, `deeper`, `comparison`으로 구분한다.
- 공식 문서 목록은 수동 큐레이션된 도메인과 정확한 링크로 시작한다. AI 생성 URL은 자동 게시하지 않는다.
- 평가: 검색어 50~100개와 기대 문서, Precision@5, Recall@10, MRR@10, 추천 근거 정확도, 분류 F1을 기록한다.

### 4.4 사용자 경험
- 상단: 전체 검색 / 최신 글 / 기술 분야 / 문제 해결 / 학습 경로.
- 검색 결과: 제목, 출처, 발행일, 태그, 추천 이유, 원문 이동; 유사 글 묶기.
- 즐겨찾기·읽음 상태는 **우선 브라우저 로컬 저장**을 검토하고 계정·동기화는 별도 수요 확인 후.
- 필터·검색어는 공유 가능한 URL 상태로 유지하며, 모바일·스크린리더·키보드 탐색을 테스트한다.
